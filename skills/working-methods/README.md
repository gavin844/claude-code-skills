# Working methods

How the agent behaves across a session: when to act, when to ask, what to say, and what counts as finished.

| Skill | What it does |
|---|---|
| [short](short) | Hard word caps on every reply: the answer first, no narration, no recaps. |
| [just-keep-working](just-keep-working) | When the next step is obvious and reversible, do it and report, instead of asking permission. |
| [correction-to-rule](correction-to-rule) | Turn a user's correction into a durable rule so the same mistake does not come back next session. |
| [midwork-triggers](midwork-triggers) | Load the right skill from what the agent is about to do mid-task, not only from the words of the request. |
| [preflight](preflight) | Before anything that writes, sends, deploys or spends, run the one check that settles the assumption, and never quietly change a rule the user set. |
| [done-means-proven](done-means-proven) | Nothing is called done without evidence from outside the work: a screenshot looked at, a job that fired, a live URL fetched. |
| [creative-mode](creative-mode) | On a request for creativity, diverge widely before converging, and aim for a bold, shippable leap over a safe tweak. |
